CAPABILITIES

五项核心机制

不是把几个 CLI 拼在一起，而是把「谁来做、做到什么程度、出错怎么办、谁能动什么」这些工程问题在平台层解决。

多 Agent 协作机制

按研发阶段拆分专职 Agent，以 Orchestrator + 状态机统一任务派发与状态流转，支持并行分支、失败重试与补偿。

Orchestrator · 状态机

人机协作边界

编译、文件操作等常规动作由 Agent 自动执行，仅在需求冲突、编译失败超阈值等关键场景请求人工介入。

Human-in-the-loop

双 Agent 结对评审

稳健派负责方案边界与风险，创新派负责替代路径，产出对比后进入设计定稿，降低单点盲区。

Adversarial Review

权限预检与确认

Agent 执行敏感操作前自动校验权限，破坏性动作强制二次确认，工具调用全程可审计。

Guardrail + RBAC

Agent 能力接入

把 MCP 工具与 Skill 注册为标准化能力，通过 Adapter 适配多执行器，新增执行器无需改动核心链路。

Tool Gateway · Adapter

本地优先架构

SQLite 落本地、Tauri 桌面与 Web 服务复用同一套数据模型与 API，进程内零云依赖，密钥不出本机。

Tauri 2 · SQLite

ARCHITECTURE

四层架构，职责清晰

接入层只负责「怎么进来」，编排层负责「谁来做」，能力层负责「能做什么」，存储层负责「记在哪里」。

接入层CLI · HTTP API · GUI WebTauri 桌面
编排层LangGraph 状态机，统一调度专职 Agent 并行分支重试补偿
能力层知识抽取 · 检索 · 评审 · Gate · 评测 MCPSkillAdapter
存储层SQLite Registry + 内容寻址 CAS 版本回滚追溯

支持的 Agent 执行器

  • Mock — 不依赖外部 CLI，用于验证界面与任务流
  • Codex CLI — 任务派发与结果回流
  • Claude Code — 复杂重构与评审
  • OpenCode / OpenClaw — 可插拔的执行器
  • Cursor CLI — 编辑器内工作流衔接

安全与边界

  • Agent 继承本机 CLI 的登录态与系统权限
  • 破坏性操作执行前强制人工确认
  • API 密钥与登录文件不出本机
  • 工作区路径绑定服务端绝对路径，避免误操作
  • 敏感动作全程留痕，可回看、可审计
QUICK START

三条命令跑起来

需要 Node.js 20+、pnpm；桌面模式另需 Rust stable 与 WebView2。

bash
# 1. 克隆
git clone https://github.com/linlisWorkTeam/ohMyWorkPanel.git
cd ohMyWorkPanel

# 2. 安装依赖
pnpm install

# 3-A. 完整 Web 服务（浏览器访问 http://127.0.0.1:8080）
pnpm run build:web
cd src-tauri
cargo run --no-default-features --bin ohmyworkpanel-server

# 3-B. 或直接启动 Tauri 桌面应用
pnpm tauri dev
