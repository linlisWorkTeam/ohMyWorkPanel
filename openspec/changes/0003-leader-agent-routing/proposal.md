# Leader Agent 路由优化（失败兜底）

## Why
Leader Agent（群管理员 Agent）通过 `@目标` 把任务委派给其他 Agent 后，目标运行失败时当前只会把 run 标记为 `failed` 并广播事件：Leader 与用户都拿不到「该重试、该换人、还是该人工介入」的结论，编排会停在原地。需要一条可预测、可观测、不会死循环的兜底路由。

## What Changes
- 在 Leader 委派链路的失败出口增加 **分类 → 重试 → 升级** 三段式路由：
  - 分类：可重试（超时/连接/限流/5xx/进程异常）、永久失败（鉴权/配置/未安装/额度）、未知、用户取消；
  - 重试：可重试/未知且未超次数时，向同一目标重派一次（深度不增加）；
  - 升级：永久失败或重试耗尽时，生成「路由升级」消息并触发 Leader 新一轮运行，由 Leader 重新指派或接手；
  - 停止：非委派运行、审阅运行、Leader 自身失败、深度超限、用户取消。
- 不新增数据库表/字段：重试次数由同 `(parent_run, agent)` 的失败 run 计数推导；升级链由 run_events 与升级消息标记。
- 每次路由决策写入 `run_events`（`route`），消息区可见升级消息，便于排障。

## Scope
`src-tauri/src/routing/`（分类/决策/DB 落地）、`scheduler::finish_failed` 挂钩、spec delta、单测与集成测试。

## Non-goals
- 不做跨群/跨工作区调度，不改 Leader 的 prompt 契约；
- 不新增设置项或数据库 schema；
- 不自动重试用户手动发起的根运行（仅委派子运行）；
- 不承诺「恰好一次」：重试是新建 run，可能产生重复输出。

## Impact
- 既有行为：失败 run 仍标记 failed、仍广播 `run_status`；新增的是之后的路由动作。
- 风险：重试放大资源消耗（默认最多 1 次）；升级运行本身失败会被 `is_leader_run` 保护直接停止。
