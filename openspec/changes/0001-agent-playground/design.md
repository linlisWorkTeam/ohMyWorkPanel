# Design: Agent 游乐园程序

## 现状与差距

| 维度 | 现在 | 需要 |
|---|---|---|
| 扩展 | 静态清单 + 进程外反代；只贡献页签 | 进程内插件：服务、依赖、生命周期、可撤销副作用 |
| 事件 | 直接函数调用 + 少量 Tauri event | 类型化事件，五种分发语义 |
| 前台 | 固定三栏壳 | 可替换的壳；同一份数据多种呈现 |
| 自治 | 单次任务调度 | 群组级 goal 驱动的多轮循环，带预算与闸门 |
| 契约 | 散落在 `docs/superpowers/specs/` | 按 capability 的行为契约 + change 流程 |

## 决策

### D1：双运行时内核，共享清单契约

**选择**：Rust 内核（`src-tauri/src/kernel/`）+ TS 内核（`src/kernel/`），各自实现同一组语义：Context、Service、`inject`、`effect/dispose`、事件分发。清单格式统一为 **manifest v2**，由 Rust 侧做发现与校验，TS 侧消费同一份 JSON。

**替代方案**：

- 起 Node 边车真跑 Cordis：能直接吃 npm 生态，但桌面端多一个运行时、Rust 服务要重新暴露一遍，且与 Tauri 生命周期耦合。
- 只做前端插件：最轻，但"所有功能可插拔"无法实现。

**理由**：本仓的重业务在 Rust。让 Rust 成为能力提供方、TS 成为呈现与组合方，比引入第三方运行时更可控；代价是两套实现需要长期对齐，用同一份契约测试来兜底。

### D2：信任模型先窄后宽

**选择**：v1 只支持**本机自写插件**（目录在受信根下），插件与服务同进程、拥有完整进程权限。权限声明（capability tokens）只在 manifest 里预留字段，不实现拦截。

**理由**：先证明组合能力，再解决隔离。过早做沙箱会把内核复杂度翻三倍，而当前没有第三方插件需求。**明确记录该风险**：进程内插件可以读写任意文件、发任意网络请求。

### D3：事件分发语义对齐 Cordis

五种模式：`emit`（观察）、`waterfall`（环绕中间件）、`parallel`（并行）、`serial`（串行）、`bail`（首个返回值短路）。事件名与模式必须在类型层面声明，避免"用了 emit 却期待返回值"。

### D4：注册即副作用

所有注册（服务、工具、页签、监听器、prompt 片段）必须返回 disposer 或包在 `effect` 里；卸载按逆序回收。**没有 disposer 的注册不允许合入**——这是热重载与插件隔离的前提。

### D5：像素前台是「壳插件」，不是新后端

**选择**：新增 `scene` 壳模式，注册为前台贡献点；只读消费现有的 group/member/run 投影，不新增 IPC、不改 schema。功能开关默认关闭，失败时回退到现有壳。

**技术**：Canvas 2D + tileset（非 DOM 精灵），React 只负责外壳与面板；角色状态机由现有 run 状态投影驱动（idle / working / blocked / done）。

**理由**：满足"只是换了个前台"的约束；同时它是插件契约的第一个真实消费者——如果像素前台都能只靠贡献点做出来，契约就站得住。

### D6：Goal 模式是调度插件

**选择**：`goal` 是一个群组级对象；循环驱动器以插件形式注册到调度服务，产出普通 run 序列，而不是把循环塞进 `scheduler.rs`。

**护栏（必须在 MVP 内）**：

- 预算：最大轮次、最大墙钟时长、最大 token
- 熔断：连续无进展 N 轮 / 连续失败 N 次即停
- 闸门：每轮或每个里程碑需要人类确认（可配置）
- 证据：每轮 plan/act/observe/judge 落库，可在群里回看
- 幂等：同一 goal 不允许并发驱动

### D7：OpenSpec 承接行为契约，version-pipeline 保留方向

两者不合并：version-pipeline 回答"下一站做什么"，OpenSpec 回答"现在承诺什么"。`docs/superpowers/specs/` 作为设计档案保留，不再新增行为契约。

## 分期与迁移

| 期 | 交付 | 验收 |
|---|---|---|
| P0 | openspec 骨架、capability 清单、本 change | 文档可读、链接有效、无代码改动 |
| P1 | kernel v0：registry + inject + effect + events；迁移 1 个真实能力（扩展宿主自身） | 单测覆盖服务生命周期与回收；门禁绿 |
| P2 | scene 只读原型：像素小人 + 状态动画 + 点击进聊天 | 默认关闭时不改变任何现有行为；开启后可回退 |
| P3 | goal MVP：单群单 goal、预算封顶、人工确认 | 一次真实 goal 跑完并留下完整证据链 |
| P4 | 按 capability 逐个插件化 | 每个迁移都有契约 delta 与回归测试 |

## 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 双内核语义漂移 | 插件行为两端不一致 | 共享契约测试集，CI 两边都跑 |
| 进程内插件无隔离 | 恶意/错误插件拖垮应用 | v1 限定本机插件；在 manifest 预留权限字段；关键路径加超时 |
| Goal 循环烧钱 | token 成本失控 | 三重预算 + 熔断 + 默认人工确认 |
| 像素前台性能 | 大量 Agent 时掉帧 | Canvas 分层渲染、离屏缓存、可视区裁剪；先做 20 个成员上限的验证 |
| 契约迁移半途而废 | 双份文档真相 | capability 清单显式标注状态；新功能必须走 OpenSpec |
