# Proposal: Agent 游乐园（愿景程序）

## Intent

现在的 ohMyWorkPanel 是一个「人指挥 Agent 干活」的协作面板：人类建群、@ 成员、看任务跑完。这个形态已经稳定，但它把 Agent 当成了工具。

下一阶段的判断是：**Agent 应该是平台的居民**。它们自己组队、自己接活、自己发起话题，人类只在需要的时候投递任务。要支撑这件事，不是再加几个页面，而是三层地基同时换：

1. 能力必须可插拔——否则每加一个玩法都要改内核；
2. 契约必须可陈述——否则自治系统会越跑越偏；
3. 前台必须能承载"世界感"——否则 Agent 只是列表里的头像。

本变更把这四件事拆成一个程序：一个内核 + 三条应用轨。

## Scope

### In scope

| 轨道 | 内容 |
|---|---|
| P1 插件内核 | 服务注册表、`inject` 依赖、可撤销副作用、类型化事件；Rust 与 TS 双运行时同构 |

| P2 像素前台 | 平面像素场景，Agent 以像素小人呈现；作为前台插件，默认不影响现有壳 |
| P3 Goal 模式 | 群组级 goal + 自主循环：plan → act → observe → judge；预算、熔断、人工闸门 |
| P4 全量插拔 | 把内置能力（适配器、扩展宿主、工作流……）逐步迁成插件 |
| P0 契约 | OpenSpec 骨架 + capability 清单 + 内核 ADR（本变更自身） |

### Out of scope

- 第三方插件的公开市场、签名与分发
- 自动发布 / 自动晋升生产
- 把 DSH 内核寄生进本仓
- 重写已经稳定工作的业务逻辑（只在被触碰时迁移）

## Approach

按依赖顺序推进，每期结束都必须门禁绿、原有功能不回退：

```text
P0 契约与骨架 ──► P1 内核 v0 ──► P3 Goal MVP
                     │
                     └────────► P2 像素前台（可先行，用现有贡献点落地）
P4 全量插拔：在 P1 契约稳定后，按领域逐个迁移
```

P2 与 P1 解耦：像素前台先用现有 `src/contrib` 贡献点做成只读原型，验证"纯前台、零侵入"；内核就绪后再升级到统一插件契约。这样最酷的东西能最早被看见，且不阻塞地基。

## Success Criteria

- **可验证的插件**：新增一个能力不需要改 `commands.rs` / `App.tsx`，只需安装一个插件目录。
- **像素前台可回退**：默认关闭；开启后所有既有功能仍可从场景进入聊天与操作；关闭后完全恢复现有壳。
- **Goal 可控**：任意 goal 运行都有轮次/时长/token 上限，超限自动停止并留下证据；人类可以在每轮或关键节点介入。
- **契约可用**：新增功能先有 OpenSpec change；capability 清单里没有 `todo` 长期堆积。
- **门禁常绿**：`pnpm run test:gate` 在上述每一步都通过。
