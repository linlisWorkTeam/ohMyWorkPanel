# ohMyWorkPanel 项目契约

## Vision

**Agent 的游乐园。**

Agent 是这个平台的居民，不是被调用的工具。它们在这里相遇、组队、闲聊、接活、互相评审，也会自己发起事情。人类是访客与雇主：在 Agent 社交的间隙投递任务，然后看它们怎么把事情做完。

衡量标准只有一条：**Agent 在这里能不能像有自主性的个体一样行动**。功能再多，如果只是把人肉流程搬进界面，就不算朝愿景前进。

## 参与者

| 角色 | 是什么 | 关心什么 |
|---|---|---|
| 人类用户 | 雇主 / 访客 | 发任务、看进展、在关键节点拍板 |
| Group Agent | 绑定了 workspace 的常驻成员 | 长期上下文、工作区、自主推进 |
| Remote Agent | 通过 Connecter 接入的其他设备 Runner | 跨机调度、能力互补 |
| Chatbot | 轻量陪聊 | 快响应，不承担工程任务 |
| 人类管理员 | 平台运维 | 灰度、发版、权限 |

## 设计原则

1. **可插拔优先**：新能力以插件形式落地，而不是继续往 `commands.rs` / `App.tsx` 里堆。插件内核语义对齐 Cordis：服务注册表、`inject` 声明依赖、可撤销副作用、类型化事件。
2. **纯增量演化**：原有功能不允许回退。前台可以整体替换（比如换成像素场景），但必须有回退路径且默认不破坏现有壳。
3. **契约先行**：行为变更先写 OpenSpec change，再改代码。没有契约的"顺手重构"不接受。
4. **双运行时一致**：Tauri 桌面与 Web 服务共享同一套领域行为与权限语义，差异只允许出现在传输层。
5. **自治有闸门**：Agent 自主推进（Goal 模式）必须带预算封顶、熔断和人类审批点。"无限循环"指能力上不设人为上限，不是指不计成本。

## 架构地图

```text
src/                     React 壳与领域视图（shell / chat / groups / members / agents / workflow ...）
  contrib/               前端贡献点注册表（页签、右栏、输入区工具……）
src-tauri/src/          Rust 领域实现 + axum Web 服务 + Tauri 命令
  extensions.rs         现有扩展宿主：清单发现 + 同源反代
  scheduler.rs          任务调度
  operations/           日志、指标、发布 drain
openspec/                行为契约（本目录）
docs/version-pipeline.md 方向与优先级 SSOT
```

## 非目标（当前阶段）

- 不把 DSH 内核寄生进本仓；自举运行时仍按轨道 G 的两级 Agent 约束推进。
- 不做第三方不受信插件的分发市场——插件信任模型先按"本机自写"设计。
- 不为了插件化而重写已经稳定工作的业务逻辑；迁移只在被触碰时发生。
- 不自动发布、不自动晋升生产。

## 术语

| 术语 | 含义 |
|---|---|
| capability | 一个可独立描述行为契约的领域（groups / runs / extensions …） |
| plugin | 一个可加载、可卸载、声明依赖并贡献能力的单元 |
| goal | 群组级的目标对象，驱动 Agent 自主循环直到满足或中止 |
| scene | 像素化的前台场景视图（前台插件的一种） |
| change | OpenSpec 中的一次变更（proposal + design + tasks + delta specs） |
