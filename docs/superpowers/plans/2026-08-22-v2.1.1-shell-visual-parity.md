# v2.1.1 Shell Visual Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the live Web UI look like `docs/ui-v2.1-shell.html` for the main three-column shell, and restyle every other Web view with the same tokens without changing those views' layouts.

**Architecture:** App remains the only state machine (auth, WS, groups, messages, members, dock). New `src/shell/*` components own the mock DOM. `src/shell/tokens.css` is the visual SSOT copied from the mock; `--lp-*` and `--s-*` alias onto it so Auth/Version/AgentConfig/Live/Invite inherit the language. v2.1.0 interaction contracts stay (four right tabs, dock, slash `/board /approve /wave`).

**Tech Stack:** React 19, Vite 7, TypeScript 5.8, existing Vitest file-read chrome tests, no new UI library.

## Global Constraints

- Version is **2.1.1** (patch). Do not open 2.2. Do not change `tauri::command`, SQLite schema, or production systemd units.
- Visual SSOT is `docs/ui-v2.1-shell.html`. Do not lock tests to `docs/ui-demo.html` `--s-*` / city backgrounds.
- Do not add Cordis. Do not add slash `/play /pause /advance /release`. Do not add `quoteMessageId`. Do not `promote-canary` without a human `approve-prod-release.sh`.
- Keep value-imports of `Brand`, `ThemeSwitcher`, `HeaderThemePop`, and `FALLBACK_CLI_ADAPTERS` (empty `#root` if dropped).
- All hooks in `App` stay before `session === "login"` early return (`src/appHooksOrder.test.ts`).
- Commit after each task. Run `pnpm exec vitest run --pool=forks --maxWorkers=1` (and `cargo test --no-default-features --lib` if Rust/version files change) before each commit. Do not set `OHMYWORKPANEL_SKIP_TEST_GATE=1`.
