# v2.2.0 Self-Marketing MVP

## Built this session

- 新增受限 Git collector：默认仅采集 committed 范围，显式模式才纳入未提交 diff；路径、字节、commit 数和命令执行时间均有上限，并过滤敏感文件与构建产物。
- 新增 `content_campaigns` 增量迁移、领域 repository/service、Planner/Writer 调度、确定性 validator、`no_content`、修改/批准/Markdown 导出状态机。
- 新增 Web/Tauri 双 API 和权限校验；Web actor 由登录身份绑定，不能通过请求体冒充审核人。
- 新增群聊 `/market` 入口、campaign 卡片、Content Brief、五渠道草稿、校验结果、修改、批准和导出交互。
- 新增操作与 API 参考文档；自动发布与数据回流仍明确不在本次范围。

## Locked product decisions

- 默认只把 committed 内容当作可公开事实；未提交 diff 必须显式选择且标记为 unreleased。
- Planner 与 Writer 是两个阶段；MVP 不新增第三个 LLM Reviewer，使用确定性 validator + 人类终审。
- 所有事实都必须经 `claim_refs -> brief -> evidence` 回溯。
- 系统允许 `no_content`，不得强迫每次产出宣传文。
- 群聊是审核入口；MVP 不连接任何外部发布平台。

## Known pitfalls

- 不要把用户工作区原文或 diff 无上限塞进 prompt。
- 不要让修改请求静默换用新的仓库状态；默认冻结 snapshot。
- 不要在 `App.tsx`、`commands.rs`、`web.rs`、`db.rs` 中堆积 marketing 领域逻辑。
- 不要把未提交内容写成“已发布”或“现已支持”。

## How to run / verify

```bash
pnpm test
pnpm run check:colors
pnpm run check:ai
cd src-tauri && cargo test --no-default-features --lib
pnpm run test:gate
```

本次验证包括：前端 125 个测试、Rust 全量 lib 测试、默认 feature `cargo check`、Web/Tauri 构建、颜色与 AI harness 门禁。真实 Web 冒烟在隔离数据目录中完成登录、打开宣传表单、基于 `HEAD` 发起 campaign，并显示 `no_content` 卡片；桌面尺寸下视觉通过，浏览器控制台零错误。

证据边界：隔离冒烟刻意使用无新增 commit 的基准验证 `no_content`，没有消费外部 Agent 配额；本机 Cursor Agent CLI 未登录，因此 Planner/Writer 的真实 CLI 内容质量仍需在具备已登录成员的环境补一次端到端抽样。编排、JSON 解析、状态落库与 Reviewer 由单元/集成测试覆盖。

## Do not regress

- 保持现有 Tauri command、Web API 与 SQLite schema 兼容；只做增量迁移。
- 保持群调度、A2A、流式消息和普通聊天行为不变。
- 不得绕过 canary 测试门禁或擅自晋升生产。
