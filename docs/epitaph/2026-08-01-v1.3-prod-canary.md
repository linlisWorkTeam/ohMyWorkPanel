# Epitaph: 生产 / 灰度双槽位 + 无缝自迭代

## Built this session

- **双环境隔离**: 生产与灰度使用独立 artifact 槽位与独立数据目录；改工作区 `dist/` / 源码 **不会** 影响生产 UI/二进制
- **生产冻结验证**:
  - `http://101.132.60.79:8080/` → 200，进程 exe=`/opt/ohmyworkpanel/prod/bin/ohmyworkpanel-server`
  - `OHMYWORKPANEL_WEB_DIST=/opt/ohmyworkpanel/prod/dist`，`OHMYWORKPANEL_DATA_DIR=/AI/ohMyWorkPanel/data`
  - 登录 `root`/`root`，群组 **`ohMyWorkPanel`**（id=`seed-group-ohmyworkpanel`）可用
  - 修改工作区 `dist/index.html` 后生产 HTML **不变**（已验证）
- **灰度就绪**: `ohmyworkpanel-canary.service` → `:8081`，数据 `/AI/ohMyWorkPanel/data-canary`（独立库）
- **端口可配置**: `main_server.rs` 读取 `OHMYWORKPANEL_PORT`（默认 `8080`）；生产当前冻结二进制若较旧则忽略该 env、仍绑 8080
- **发布脚本**: `freeze-prod.sh` / `deploy-canary.sh` / `promote-canary.sh` + `release-layout.sh`

## Key files

| 文件 | 说明 |
|---|---|
| `/opt/ohmyworkpanel/prod/{bin,dist,meta}` | **生产冻结槽**（运行时只读此槽产物） |
| `/opt/ohmyworkpanel/canary/{bin,dist,meta}` | 灰度槽 |
| `/AI/ohMyWorkPanel/data` | **生产 SQLite**（含 ohMyWorkPanel 群组）— promote 永不覆盖 |
| `/AI/ohMyWorkPanel/data-canary` | 灰度 SQLite |
| `scripts/freeze-prod.sh` | 冻结产物入 prod（`from-running` / `from-workspace`） |
| `scripts/deploy-canary.sh` | 构建(可选)并部署到 canary + restart |
| `scripts/promote-canary.sh` | canary → prod（仅 bin+dist；备份旧 prod 到 `prod-prev-*`） |
| `scripts/release-layout.sh` | 路径/端口常量 |
| `deploy/systemd/ohmyworkpanel.service` | 生产 unit 模板 |
| `deploy/systemd/ohmyworkpanel-canary.service` | 灰度 unit 模板 |
| `src-tauri/src/main_server.rs` | `OHMYWORKPANEL_PORT` 绑定 |

## Locked product decisions

| 项 | 选择 |
|---|---|
| 生产端口 | **8080**（对外继续对话的环境） |
| 灰度端口 | **8081** |
| 生产数据 | 固定 `/AI/ohMyWorkPanel/data`；**promote 只换二进制与前端，不换库** |
| 灰度数据 | `/AI/ohMyWorkPanel/data-canary`（可随时清库重试） |
| 工作区 `dist/` | 仅构建暂存；**生产不读此路径** |
| 自迭代路径 | 改代码 → `deploy-canary.sh` 测通 → `promote-canary.sh` → 生产无缝升级 |
| 继续对话入口 | 生产环境群组 **ohMyWorkPanel**（账号 `root`/`root`） |
| 代理 | `:9090` proxy 仍指向本机生产后端（localhost） |

## How to run / verify

```bash
# 生产健康
systemctl status ohmyworkpanel.service
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/
# 登录后应看到 ohMyWorkPanel
curl -sS -X POST http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"root","password":"root"}'

# 部署灰度（低内存机器务必单作业）
sync; echo 3 > /proc/sys/vm/drop_caches   # 可选
/AI/ohMyWorkPanel/scripts/deploy-canary.sh          # 含 build
# 或已构建: /AI/ohMyWorkPanel/scripts/deploy-canary.sh skip
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/

# 灰度验证通过后晋升生产（不碰生产 DB）
/AI/ohMyWorkPanel/scripts/promote-canary.sh

# 紧急：仅重新冻结当前运行产物
/AI/ohMyWorkPanel/scripts/freeze-prod.sh from-running
systemctl restart ohmyworkpanel.service
```

低内存构建：

```bash
export CARGO_BUILD_JOBS=1
export NODE_OPTIONS=--max-old-space-size=1024
# 复制用 /bin/cp -f（shell cp 可能交互）
```

## Do not regress

- **禁止** 把生产 `ExecStart` / `OHMYWORKPANEL_WEB_DIST` 指回 `/AI/ohMyWorkPanel/dist` 或 workspace `target/release`（否则改代码即污染生产）
- **禁止** 灰度与生产共用 `OHMYWORKPANEL_DATA_DIR`（schema 试验会毁掉对话群组）
- **禁止** `promote-canary.sh` 覆盖 `/AI/ohMyWorkPanel/data`
- 生产群组 **`ohMyWorkPanel` / `seed-group-ohmyworkpanel`** 与 seed 用户 **`root`/`root`** 必须保持可登录可用
- systemd 变更后同步回 `deploy/systemd/*.service`，避免下次部署漂移

## Known pitfalls

- 机器约 **1.8GB RAM**：并行 cargo/node 易 OOM；构建务必 `CARGO_BUILD_JOBS=1` + 限制 Node heap
- 生产槽当前冻结二进制可能 **早于** `OHMYWORKPANEL_PORT` 提交；晋升一次 canary 后两端均支持端口 env
- 灰度库是空种子库，**没有**生产聊天历史；测功能用灰度，聊业务用生产
- `/usr/local/bin/ohmyworkpanel-server` 已不再被 systemd 使用（遗留副本可忽略）
- **前台「React 崩了」假象**：常见为 promote 中断致 prod dead、HTTPS 下 `ws://` 被拦、或 hashed assets/SW 错配白屏 — 发版必须跟 `docs/release-checklist.md` §F
