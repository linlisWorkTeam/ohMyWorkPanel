# Epitaph: v1.0–v1.1 PM 前端 UI 与 API 层完整整合

## Built this session

- **后端 PM 功能** (Phase 1–3, by previous agent): RoadmapItem/Feature/FeatureTask 三个数据库表 + 13 个 Tauri 命令 + web.rs 路由
- **前端 API 层修复**: 补全 `api.ts` / `api-tauri.ts` / `api-web.ts` 的 13 个 PM API 函数
- **api-web.ts URL 修正**:
  - `addMember` URL: `/api/members` → `/api/groups/${groupId}/members`
  - `setAdmin`: 路径参数 → PUT JSON body (`{member_id}`)
  - `sendMessage` 返回类型: `Message` → `{message, runIds}`
  - 移除 `detectAgent`（无对应 web route）
- **PM 前端 UI** (`src/PmPanel.tsx` + styles.css):
  - 右侧面板新增 "群成员" / "项目管理" 标签切换
  - 路线图视图: 按状态分组、创建/编辑/删除、优先级/日期展示
  - 功能看板视图: Backlog / In Progress / Review / Done 四列看板
  - 功能卡片: 可展开子任务清单、勾选/添加/删除子任务
  - 快捷状态跳转按钮
- **测试验证**: Rust 8/8 通过, Frontend Vitest 1/1 通过, cargo build 成功

## 已知问题

- **无 PM 单元测试**: PM CRUD 遵循现有模式，但缺乏独立单元测试
- **Web 版无登录 UI**: App.tsx 缺乏 auth 流程，Web 版需要用户自行处理
- **`bootstrap` web 路由**: `/api/groups` 返回 `Vec<GroupState>` 而非 Tauri 版的 `{groups: GroupState[]}`。前端 App.tsx 的 `bootstrap().groups` 调用在 web 模式下需要适配
- **Cargo.lock CRLF 警告**: Windows 开发环境正常行为

## Do not regress

- `tauri::command` 签名、前端 API 调用、SQLite schema 的向后兼容
- `api.ts` / `api-tauri.ts` / `api-web.ts` 三文件需保持同步
- PmPanel 组件导入 `api.ts`，web 构建时通过 Vite alias 自动切换到 `api-web.ts`
- 右侧面板的 `member-panel header` 样式同时服务于成员列表和 PM 面板
