# Epitaph: v0.4 Tauri + Web 双模式与多用户基础设施

## Built this session

- **Tauri + Web 双模式**: 完成了 Axum web 服务器 (`main_server.rs`)、路由层 (`web.rs`)、JWT 认证 (`auth.rs`)、SQLite 多用户表 (`users`, `message_attachments` BLOB)
- **前端双模式**: `api-web.ts` (fetch + WebSocket)、`api-tauri.ts`、stubs 桩模块 (`tauri-core`, `tauri-dialog`, `tauri-event`) 和 `vite.config.web.ts`
- **`api.ts` dispatcher**: 运行时自动检测 Tauri/Web 环境（通过 `resolve.alias` 机制）
- **Tauri 桌面构建**: 添加 `main.rs` 入口，修复 `default-run` + `[[bin]]` 配置，成功通过 `pnpm tauri build` 创建 NSIS 安装器
- **产出验证**: Tauri 桌面版启动确认，所有产出复制到 `output/`
- **OCR 增强**: `ocr_image_base64` 命令（支持剪贴板粘贴 OCR）
- **构建脚本**: `build:web` 脚本支持纯前端构建

## Locked product decisions

- **数据库**: SQLite（rusqlite 0.32, bundled），文件存 BLOB 在 `message_attachments` 表
- **Web 框架**: Axum 0.8.9 + tower-http (cors + fs)
- **双模式策略**: Tauri 桌面版是主交付路径，Web 版是辅助路径
- **前端 API 层分离**: 通过 Vite resolve.alias 实现，而非运行时动态 import
- **适配器架构**: `AdapterKind` 枚举 + `build_args`，CLI 候选在 `candidate_executables`
- **应用名**: LinlisWorkPanel，标识符 `com.linlis.workpanel`

## Known pitfalls

- Web 服务器 routes 不完整（缺少 members CRUD、runs、settings、OCR、preset-roles）
- App.tsx 没有登录/注册 UI（Web 版需要 auth 流程但当前直接使用 Tauri IPC）
- `vite.config.web.ts` 使用 `import.meta.url` 解析 `__dirname`（ESM 要求）
- `output/` 下有旧版 exe 未清理（`linlis-work-panel.exe`, `LinlisWorkPanel.old.exe`）
- `Cargo.lock` 的 LF/CRLF git warning（Windows 开发环境正常行为）

## How to run / verify

```powershell
# Tauri 桌面版
.\output\LinlisWorkPanel.exe

# Web 服务器（需要先补充完整 routes）
.\output\linlis-work-panel-server.exe
# 浏览器打开 http://localhost:8080

# 开发模式
cd D:\AI\LinlisWorkPanel
pnpm dev          # 前端 dev server (port 1420)
pnpm tauri dev    # Tauri 桌面 dev
pnpm run build:web # 纯前端构建

# Rust
cd src-tauri
cargo test
cargo build --release
```

## Do not regress

- `tauri::command` 签名、前端 API 调用、SQLite schema 的向后兼容
- Tauri build 需要 `default-run` 和 `[[bin]]` 才能找到主二进制
- `api.ts` 目前是 Tauri 版，靠别名机制转到 web 版。修改 `api.ts` 需同时更新 `api-web.ts`
- 新适配器需实现 `AdapterKind` + `build_args` + 更新前端 `<select>` 文案
